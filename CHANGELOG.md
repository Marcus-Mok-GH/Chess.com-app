### Added
- Settings page revamp: the /settings experience was rebuilt around clearer information hierarchy without changing any setting or API contract. Added a quick-jump section nav with anchor deep-links (`/settings#privacy` still resolves), moved the Account section to the top with a responsive ratings grid, merged Sound + Haptics into one section, and replaced the inline privacy-policy wall with a "Privacy Policy" link row to the existing /privacy page. Destructive actions are now safer: both "Resign all live games" (previously a bare `window.confirm` — one of the two intentional behavior changes, the styled in-page confirmation still blocks accidental forfeits) and "Reset to Defaults" (newly guarded, and disabled while settings already match defaults) use a two-step armed confirmation with Cancel and auto-timeout. Accessibility basics landed across the page: every toggle is wired to its visible label (`for`/id + `aria-describedby`), the volume slider announces its value (`aria-valuetext`), pollinations status and resign/reset feedback use `role=status`/`role=alert` + `aria-busy`, the theme picker is a labelled `role=group`, and sections are focusable focus targets for anchor navigation. A new `pages/Settings.test.jsx` pins the toggles, theme/volume controls, the two-step confirms, resign outcomes (success/empty/failure), parent links, and coach status states; the file is registered in the root test script.

### Added
- Hardened automatic schema creation: the runtime paths (server startup, serverless cold-start warm-up, per-query self-heal) were already idempotent, but the stale manual `setup-db.sql` still claimed to "create the database schema" while defining only 8 of ~22 tables — anyone provisioning a fresh database with it got a broken half-schema (no `puzzle_stats`, `lessons`, `sessions`, `clubs`, `elo_history`, …). It is now a no-op pointer to `db/init.js` (the single source of truth), and a schema guard test pins the `puzzle_stats` table (including its `rating` column) so a future schema edit can't silently drop puzzle Elo persistence.
- Puzzle Elo now actually persists to the database per account: the puzzles page was saving the stats payload with a `streak` key while `PUT /api/puzzles/stats/user` requires `currentStreak`, so every save failed validation with a 400 and the rating (plus solved/streak counts) never reached the `puzzle_stats` table. Stats also load whenever the login state changes — signing in through the header modal while on the puzzles page now fetches the account's saved rating instead of letting the first solve overwrite it with session defaults (0 solved / 400), and signing out resets the local counters so session stats can't leak into the account row.
- The Admin page is now genuinely admin-only and reachable by admins: the backend already sent `isAdmin` on the session, but the client dropped the flag, so even real admins saw "You need admin access" and the sidebar never showed the Admin link. The flag now flows into the user context, and `/admin` is guarded at the route level — non-admins (including guests and logged-out users) are redirected home instead of landing on an admin page shell.
- Fixed the "unstyled page" after deployments: the service worker cached the app shell and served it stale-first, so after a new deploy the cached HTML linked to dead fingerprinted assets and the whole page rendered without CSS (quick-reaction buttons collapsed into a word string). Navigations are now network-first, the shell is no longer cached, and the production cleanup purges the old Cache Storage entries. Added proper styling for the quick-reactions row.
- Fixed "Session identity does not match player" errors on resign/move/local-save: clients had mirrored a truncated session id from `/auth/session` into the localStorage Bearer token, which then failed validation while a valid cookie was present. The server now falls back to the httpOnly cookie when a presented Bearer token fails, expired sessions return 401 instead of the misleading 403, and the client no longer mirrors the truncated prefix.
- Serverless DB warm-up now skips schema DDL when the stored schema version matches: cold starts stop taking ACCESS EXCLUSIVE locks on the users table, which was blocking account endpoints (504s) whenever the warm-up transaction stalled. Concurrent inits serialize via an advisory lock and all schema work runs with a 10s lock timeout.
- Admin account management: admins can search accounts by username or email and ban (with an optional reason), unban, or permanently delete them from a new Admin page. Banned users are signed out immediately and blocked from signing back in.
